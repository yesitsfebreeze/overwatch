overwatch: installation instructions for any coding agent

You are a coding agent installing overwatch for yourself or for an agent the
user names. Already installed for that host: do UPDATE and stop. Otherwise do the COMMON
STEPS and exactly one HOST section.
- Edit no file outside the paths named here.
- Read a config file before changing it and merge; never replace it wholesale.
- Report every command and its outcome. A step fails: stop and report it.

WHAT IT DOES

- Plan: tasks and guards (one yes/no question per deliverable, ideally with a
  shell `check`; exit 0 = upheld).
- Edit gate: file edits are refused until the plan has a task and a guard.
- Stop hold: a stop is refused while a task is open or a check fails.
- Record: a kind of refusal caught 3 times in 30 days adds one lesson line to
  every later session start.
- Changelog: `changelog <what changed>` writes a bullet under the current
  version in CHANGELOG.md; `changelog --backfill` groups git history by the
  version each commit saw, keeping bullets already written.

One core (host/core.ts) serves every host, through native plugin code, command
hooks (`overwatch hook <host> <event>`) or the MCP server (`overwatch mcp`).
State lives in .overwatch/ in the project root; the session start asks to
gitignore it.

UPDATE (when `command -v overwatch` prints a path)

U1. Find the checkout:
      OW="$(cd "$(dirname "$(readlink "$(command -v overwatch)")")/.." && pwd)"
      test -x "$OW/bin/overwatch" && git -C "$OW" rev-parse --show-toplevel   # expect $OW
    Fails: ask the user for the checkout; never clone a second.
U2. Check:
      git -C "$OW" fetch --quiet origin
      git -C "$OW" log --oneline HEAD..@{u}
    Exit 0 and no output: current. Report `git -C "$OW" log --oneline -1` and stop.
U3. Update, fast-forward only. Local changes (`git -C "$OW" status --short`) or
    a refused pull: stop and report; never stash, reset or force.
      git -C "$OW" pull --ff-only
      cd "$OW" && bun test ./host/host.check.ts                # expect 0 fail
U4. Refresh the host. Hosts that run the checkout itself are done (the
    `overwatch` binary, pi, Hermes, Gemini, Cursor, Droid, Claude Code with
    --plugin-dir). Hosts that run a copy:
      Claude Code (installed plugin):
        claude plugin marketplace update overwatch
        claude plugin update overwatch@overwatch
      Codex CLI, Copilot CLI: run the HOST section's install commands again.
      opencode: cd "$OW/adapters/opencode" && bun install
    The pulled install.txt names a hook or config entry the host lacks: merge
    it as the HOST section says.
U5. Run the HOST section's VERIFY line. Tell the user the commits pulled, the
    VERIFY output, and that the agent must be restarted.

COMMON STEPS (every host)

1. git and bun on PATH:
     git --version && bun --version
   Missing bun: `curl -fsSL https://bun.sh/install | bash`, then a new shell.
2. Source in a stable directory, $OW. The user already has a checkout: set OW
   to it and skip the clone.
     OW="$HOME/dev/overwatch"
     git clone https://github.com/yesitsfebreeze/overwatch "$OW"
3. Binary on PATH (every hook and MCP config calls `overwatch`); ~/.local/bin
   must be on PATH for the agent's processes:
     mkdir -p "$HOME/.local/bin"
     ln -sf "$OW/bin/overwatch" "$HOME/.local/bin/overwatch"
     overwatch help
     echo '{}' | overwatch hook codex Stop; echo "exit $?"     # expect exit 0
4. Verify the core:
     cd "$OW" && bun test ./host/host.check.ts                 # expect 0 fail
5. Do the HOST section, run its VERIFY line, then restart the agent.

HOST: Claude Code
  Native plugin: every part and tool.
    claude plugin marketplace add "$OW"
    claude plugin install overwatch@overwatch --scope user
  Needs CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 in the environment Claude Code
  starts with. Live edits: `claude --plugin-dir "$OW"`.
  VERIFY: cd "$OW" && claude plugin validate . && claude plugin test .

HOST: OpenAI Codex CLI
    codex plugin marketplace add "$OW"
    codex plugin add overwatch@overwatch
  The user must open `/hooks` in Codex and trust the four overwatch hooks
  (SessionStart, UserPromptSubmit, PreToolUse, Stop); you cannot approve them.
  Versions that still gate hooks need `[features] hooks = true` in
  ~/.codex/config.toml; add it only if absent.
  VERIFY: new session, ask "call overwatch plan_show"; it answers "No tasks, no guards."

HOST: pi (earendil-works pi-coding-agent)
    pi install "$OW"
  Try without installing: pi -e "$OW/adapters/pi/overwatch.ts"
  VERIFY: in a scratch git repo,
    pi --no-session -p "Create hello.txt containing hi with the write tool."
  The first write is refused until the plan exists; the run ends with the task
  done and hello.txt present.

HOST: opencode (2.x, @opencode/plugin)
    cd "$OW/adapters/opencode" && bun install
  Add the directory to the "plugins" array (plural; local entries must be
  directories) in ~/.config/opencode/opencode.jsonc (user) or
  .opencode/opencode.json (one project), keeping existing entries:
    "plugins": [ ..., "<absolute path of $OW>/adapters/opencode" ]
  VERIFY: opencode run "call overwatch_plan_show"  →  "No tasks, no guards."

HOST: Hermes Agent (NousResearch)
    mkdir -p ~/.hermes/plugins
    ln -sfn "$OW/adapters/hermes/overwatch" ~/.hermes/plugins/overwatch
    hermes plugins enable overwatch
  Merge into ~/.hermes/config.yaml (keep existing servers):
    mcp_servers:
      overwatch:
        command: overwatch
        args: ["mcp"]
  Limit: no general stop hook; pre_verify fires only on turns that edited
  code, so the stop hold covers those turns only.
  VERIFY: hermes plugins list shows overwatch enabled; a new session can call plan_show.

HOST: Google Gemini CLI
    gemini extensions link "$OW/adapters/gemini"
  Gemini asks for consent to the extension's hooks: the user confirms it.
  VERIFY: gemini extensions list shows overwatch; /mcp lists the overwatch tools.

HOST: GitHub Copilot CLI
    copilot plugin install "$OW"
  Limit: Copilot drops hook output on prompt submit, so the plan reminder
  rides sessionStart only. The repository folder must be trusted.
  VERIFY: copilot plugin list shows overwatch; a session can call plan_show.

HOST: Cursor (IDE and cursor-agent)
    mkdir -p ~/.cursor/plugins/local
    ln -sfn "$OW" ~/.cursor/plugins/local/overwatch
  Then the user runs "Developer: Reload Window".
  Limits: the reminder rides sessionStart; only Cursor's "Write" tool is
  gated; the stop hold is a followup_message (loop_limit 8). cursor-agent fires
  only part of the hooks.
  VERIFY: Cursor Settings → Hooks and MCP list overwatch.

HOST: Factory Droid
  Droid reads hooks/hooks.json, which here is Claude Code's module, so install
  by config:
    droid mcp add overwatch overwatch mcp
  Merge every event of $OW/adapters/droid/hooks.json into ~/.factory/hooks.json
  (append to existing event arrays; create the file if absent).
  VERIFY: a new droid session can call plan_show; an Edit before task_add is refused.

HOST: anything else
  MCP client: register a stdio server named overwatch, command `overwatch`,
  args ["mcp"], started in the project directory (or with OVERWATCH_PROJECT set
  to the project path). That gives the tools.
  Command hooks in Claude Code's format (stdin JSON with cwd and tool_name;
  hookSpecificOutput.additionalContext; permissionDecision deny; decision block
  on stop): point them at `overwatch hook claude <Event>` for SessionStart,
  UserPromptSubmit, PreToolUse (file write/edit tools) and Stop.
  Neither: MCP server only, and tell the user the edit gate and stop hold are
  not active on this host.

AFTER INSTALL

Tell the user: what you installed, for which agent, the VERIFY output, any
approval still theirs to give (Codex /hooks, Gemini consent, Cursor reload) and
the host's limits. Uninstall reverses the steps; a project's state is its
.overwatch/ folder and can be deleted.
